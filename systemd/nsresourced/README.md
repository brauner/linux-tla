# TLA+ model of the systemd-nsresourced user namespace registry

Tree: systemd v262-rc2-60-ge96ff3b5b9.

`systemd-nsresourced` hands unprivileged clients a transient 64K UID/GID
range for a user namespace they created: `systemd-nspawn
--private-users=managed`, the executor for `PrivateUsers=managed`,
`systemd-dissect`, image management.  A worker process serves the
`AllocateUserRange` call: under a lock file in the registry directory it
checks the inode number of the namespace against the existing entries,
picks a free range, writes the entry, adds the inode to the BPF-LSM map
that keeps the range off persistent file systems, writes the namespace's
`uid_map`, and pushes the namespace fd into PID 1's file descriptor store
with `FDSTORE=1` (a push that never arrives, see the end).  Later calls delegate a cgroup and a veth to the
namespace.  When the kernel frees the namespace, a kprobe on
`retire_userns_sysctls()` reports its inode through a BPF ring buffer and
the manager releases everything: the map entry, the fd store entry, the
cgroup, the interface, the registry files.  The kernel reuses inode
numbers, so the registry also records the namespace id (`NS_GET_ID`) and
probes it before it believes an entry.

The model is the registry directory, the BPF map and ring buffer, PID 1's
fd store, the kernel's namespaces with their inode numbers and ids, two
clients (one nspawn-like, one executor-like), the worker per request, the
manager, and a manager restart with its startup sweep.

## Running it

TLC ships in `tla2tools.jar` (https://github.com/tlaplus/tlaplus/releases,
version 2.19 was used).  Java 17 or newer.

    export TLA2TOOLS=/path/to/tla2tools.jar
    ./check.sh registry_fixed 8        # one configuration
    ./check-all.sh                     # every configuration, summary in logs/summary.txt

The two-inode configurations finish in under a minute.  The three-inode
liveness proof (5M states, a 36M-node liveness graph) took 3.5 minutes
with 32 workers and a 48g heap; with a 4g heap the JVM died in the final
temporal check without a word in the log.

The runs above are in the foreground.  For anything that takes longer than a
coffee, start it detached so that it survives the terminal and the ssh session,
and check on it later:

    ./start.sh registry_fixed_3inodes 32 32g          # like check.sh, detached: pid in logs/<cfg>.pid, output in logs/<cfg>.log
    ./run-parallel.sh 8 8g           # every configuration, each detached
    ./status.sh                      # what every run is doing (pass, violation, running, dead)
    ./resume.sh registry_fixed_3inodes 32 32g         # a dead run continues from its last checkpoint
    ./summarize.sh                   # logs/summary.txt for fill-results.py
    ./vm-probe.py --tree ~/src/systemd   # the fd store experiment in a throwaway VM (needs a built mkosi image)

TLC writes a checkpoint every ten minutes into `/tmp/$USER-tlc-nsresourced/<cfg>/`
(`TLC_METADIR`, `TLC_CHECKPOINT`); `resume.sh` finds the newest one in the log.

## What is in the model

### Actions and the code they stand for

| Action | Code |
|--------|------|
| `Create` | `userns_acquire_empty()` in the client and the `AllocateUserRange` call: a fresh namespace with a free inode number and the next id, one client reference |
| `WLock`, `WSlot`, `WRange`, `WPush` | the worker: `userns_registry_lock()`; `inode_slot_is_available()` (an entry for the inode with another id is stale and released, without the id check any entry is `UserNamespaceExists`); `allocate_one()`/`uid_is_available()` with `registry_range_is_available()` reaping a dead owner, `userns_registry_store()`, `userns_restrict_register_by_fd()`, `write_userns()`, the lock dropped; the `FDSTORE=1 FDNAME=userns-<inode>` push (which never arrives, see below) and the reply |
| `WResources` | `AddControlGroupToUserNamespace` and `AddNetworkToUserNamespace` of the nspawn client: entry loaded by inode, verified by id, cgroup and veth created and recorded |
| `Drop` | the container exited, the service stopped: the client's references are gone |
| `NsDie` | the last reference is gone: `free_user_ns()`, `retire_userns_sysctls()`, the kprobe's `bpf_ringbuf_output()` if a map knows the inode (dropped when the ring buffer is full), the inode number free again |
| `MgrTake`, `MgrRelease` | `ringbuf_event()`: the lock, `manager_release_userns_by_inode()` with the liveness probe of `manager_release_userns_by_info()`, `userns_registry_release_by_info()` or the inode-only cleanup |
| `Restart` | `manager_startup()`: fd store entries without a registry entry released, `userns_registry_reap_if_dead()` per entry, `manager_restore_userns_policy()` for the live ones; in-flight requests fail; PID 1 keeps the fd store |

### Switches

| Constant | Meaning |
|----------|---------|
| `FDSTORE_PINS` | PID 1 keeps the fd the worker pushes with `FDSTORE=1`; an open nsfs fd references the namespace, so it cannot die while registered.  TRUE is what the source says, FALSE is what runs (see below) |
| `FIX_NSID_VERIFY` | 01e6465b55 "Verify user namespace identity on registry lookup": the id in the entry, the stale-slot release, the manager's probe before a release |
| `FIX_REAP_ON_ALLOC` | a77838a950 "reclaim ranges from dead namespaces during allocation" |
| `FIX_STARTUP_SWEEP` | 23f2204718 "detect and clean up registry entries for dead user namespaces" |
| `FIX_RINGBUF_LOCK` | `ringbuf_event()` takes the registry lock |
| `Inodes`, `Ranges`, `IdMax`, `RingCap`, `RestartBudget` | the inode pool, the range pool, how many namespaces the run creates, the ring buffer size, how often the manager may restart |

### Properties

| Property | Meaning |
|----------|---------|
| `LiveRangesDisjoint` | two live namespaces never map the same transient range |
| `ManagedCoversLive` | a live namespace that holds a range is in the BPF map |
| `ResourcesOfLiveKept` | the cgroup and the interface delegated to a live namespace are not destroyed behind its back |
| `RegistryConsistent` | the registry never describes a live namespace under the wrong inode |
| `NoStarvationByDead` | a request fails with `NoDynamicRange` only when every range is held by a live namespace |
| `UnusedNamespaceDies` (liveness) | a namespace nobody references any more dies |
| `RangeReclaimed` (liveness) | the entry of a dead namespace is released |

Fairness is weak fairness on the workers, the manager and the kernel's
freeing.  Clients may keep a namespace forever, restarts never have to
happen, the ring buffer drops what does not fit.

### Abstractions

- Only 64K "managed" allocations: no self mappings, no delegated ranges,
  no nested namespaces, no user database side, no polkit.
- A client holds one reference (its fd and the processes it runs in the
  namespace) and drops it in one step.  The worker's own dup of the fd is
  folded into the request: the namespace cannot die while its request is
  in flight.
- The steps under the registry lock are atomic, including the multi-file
  `userns_registry_store()`; the lock therefore only orders the model's
  steps.  The fd store push after the lock is a step of its own, as in
  the code.
- Cgroups are found by id, interfaces by name derived from the namespace
  id; both are one resource per nspawn client.
- A restart is atomic: workers die and their requests fail, PID 1 keeps
  the fd store (`FileDescriptorStorePreserve=restart`), the pinned maps
  and ring buffer survive, the sweep runs before the socket is served.

## What the model says beyond the code

- **The fd store push never arrives, and that is what keeps the daemon
  working** (`registry_fdstore_pins` against `registry_fixed`).  The worker
  pushes the namespace fd to PID 1 with `FDSTORE=1` after every allocation,
  `AddMountToUserNamespace` pushes the mount fd the same way, the unit has
  `FileDescriptorStoreMax=4096`, and `manager_scan_listen_fds()` reads the
  inodes back from the store after a restart.  None of it runs:
  `safe_fork()` unsets `$NOTIFY_SOCKET` in the child unless the caller
  passes `FORK_KEEP_NOTIFY_SOCKET`, `start_one_worker()` does not, and
  `sd_pid_notifyf_with_fds()` returns 0 without a socket.  `vm-probe.py`
  (systemd 262-rc2 on a 7.1 kernel) shows it: the manager has
  `NOTIFY_SOCKET` in its environment and no worker does, PID 1 logs no
  `FDSTORE=1` from the service, `NFileDescriptorStore` is 0 while the
  namespace is registered, and two seconds after the client dropped its
  last fd the entry is gone; the one fd store message PID 1 ever sees from
  nsresourced is the `FDSTOREREMOVE=1` of the release, for an entry that
  was never there.  Had the push arrived, an nsfs fd holds a reference on
  the namespace (`ns_get_path()` → `userns_get()`, dropped in
  `nsfs_evict()`): `free_user_ns()` never runs, the kprobe never fires, the
  id probe finds the namespace alive, and the range, the registry entry,
  the delegated cgroup and the veth stay allocated for as long as the
  service runs (`registry_fdstore_pins`).  Every reclamation path in the
  code presumes that the namespace can die.  The pushes, the restore at
  startup and the store limit are dead code to remove, not a fork flag to
  add; the systemd branch `work.systemd.nsresourced.fdstore` removes them
  and adds a TEST-13-NSPAWN case that a managed container's namespace is
  released with the container.
- **The id in the registry is what makes inode reuse safe**
  (`registry_no_nsid`): a death event that arrives after the kernel
  handed the inode number to a new registered namespace would release
  the new namespace's entry, drop it from the BPF map and free its range
  for a third namespace.
- **A dropped death event is only recovered by an allocation that runs
  out of ranges, or a restart** (`registry_ringbuf_drop`,
  `registry_no_reap`): the ring buffer has room for 1024 inodes, and the
  reap-on-allocation logic only runs for a range a request wants.  Noted
  in systemd's TODO.md on the same branch, with the two ways out: count
  the events the kprobe could not deliver and sweep when the count moved,
  or sweep the registry periodically.
- The manager's lock in `ringbuf_event()` protects the multi-file
  registry writes, which the model does not split; with atomic entries
  nothing depends on it (`registry_no_ringbuf_lock`).
