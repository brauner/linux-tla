# TLA+ model of systemd-executor and the manager that spawns it

Tree: systemd v262-rc2-60-ge96ff3b5b9.

PID 1 does not fork services itself any more: `exec_spawn()` serializes
the unit and `posix_spawn()`s the pinned `systemd-executor`, which
deserializes, sets up the sandbox in `exec_invoke()` and `execve()`s the
payload.  Everything the manager learns about that process afterwards
arrives asynchronously through its event loop: the uid/gid the executor
resolved, the pidref of a pid namespace child, the handoff timestamp, the
bytes and the EOF on the `exec_fd` pipe that implement `Type=exec`, the
SIGCHLD of every child, and the cgroup running empty.  `manager.h` orders
those sources with `EVENT_PRIORITY_*`, `service.c` decides what each one
means in each state, and `unit_kill_context()` sends the signals.  The
executor also leaves helpers behind: the `(sd-pam)` child that closes the
PAM session when the payload dies, and, for `PrivatePIDs=`, a parent
that hands its child over to the manager and exits.

The model is one service, the executor, its helpers and the payload, and
the manager dispatching the highest-priority readable source, one per
step, against every interleaving of the processes.  The priority table
and the individual protections are switches: with a switch flipped TLC
finds the trace the protection prevents, with everything on it proves
the properties.

## Running it

TLC ships in `tla2tools.jar` (https://github.com/tlaplus/tlaplus/releases,
version 2.19 was used).  Java 17 or newer.

    export TLA2TOOLS=/path/to/tla2tools.jar
    ./check.sh exec_fixed 8            # one configuration
    ./check-all.sh                     # every configuration, summary in logs/summary.txt

The state spaces are small (hundreds to a few thousand states); every
configuration finishes in under a minute on a laptop, `run-parallel.sh`
runs them all at once.

The runs above are in the foreground.  For anything that takes longer than a
coffee, start it detached so that it survives the terminal and the ssh session,
and check on it later:

    ./start.sh exec_fixed 32 32g          # like check.sh, detached: pid in logs/<cfg>.pid, output in logs/<cfg>.log
    ./run-parallel.sh 8 8g           # every configuration, each detached
    ./status.sh                      # what every run is doing (pass, violation, running, dead)
    ./resume.sh exec_fixed 32 32g         # a dead run continues from its last checkpoint
    ./summarize.sh                   # logs/summary.txt for fill-results.py

TLC writes a checkpoint every ten minutes into `/tmp/$USER-tlc-executor/<cfg>/`
(`TLC_METADIR`, `TLC_CHECKPOINT`); `resume.sh` finds the newest one in the log.

## What is in the model

Three processes: `E`, the executor the manager spawned (the main pid);
`C`, the child `setup_private_pids()` forks for `PrivatePIDs=`, a child
of the manager from birth thanks to `FORK_DETACH`; `P`, the `(sd-pam)`
child of `setup_pam()`.  The process that reaches `execve()` becomes the
payload and keeps its pid.  The manager is the `Service` object: its
state, result, main pid, watched pids, `exec_fd_hot`, the start job, the
`TimeoutStartSec=` timer, and the readable sources of its event loop.
The kernel keeps the pipe write ends, the datagram queues, zombies,
parents, pending signals and `cgroup.events`.

### Actions and the code they stand for

| Action | Code |
|--------|------|
| `InitPhase`, `Creds`, `Setup`, `Sandbox` | `exec_invoke()`: the fd shuffling and `close_remaining_fds()` (EXIT_FDS), `get_user_creds()` and `send_user_lookup()` (EXIT_USER), `cg_attach()` and the stdio/directory/credential setup (EXIT_CGROUP), namespaces, capabilities, `enforce_user()` and seccomp (EXIT_SECCOMP) |
| `Pam`, `PamSync` | `setup_pam()`: `pam_open_session()`, the fork of `(sd-pam)` with every fd inherited (EXIT_PAM), `barrier_place_and_sync()` |
| `Ns`, `NsFork`, `NsExit` | `setup_private_pids()`: `pidref_safe_fork(FORK_NEW_PIDNS\|FORK_DETACH)`, the pidref sent to the manager, the errno written to the child, `_exit(EXIT_SUCCESS)` (EXIT_NAMESPACE) |
| `Hot`, `Handoff`, `Execve` | `exec_fd_mark_hot(true)`, `send_handoff_timestamp()`, `fexecve_or_execve()` with O_CLOEXEC closing `exec_fd`; on failure `exec_fd_mark_hot(false)` and EXIT_EXEC |
| `PayloadExit`, `Killed` | the payload exits, a process dies of a pending SIGTERM (SIG_DFL) or SIGKILL |
| `PCloseFd`, `PDrop`, `PPrctl`, `PPlace`, `PCheck`, `PWait`, `PClose`, `PExit` | the `(sd-pam)` child: `safe_close(exec_fd)`, `fully_set_uid_gid()`, `prctl(PR_SET_PDEATHSIG, SIGTERM)`, `barrier_place()`, `if (getppid() == parent_pid) sigwait(SIGTERM)`, `if (getppid() != parent_pid) pam_close_session_and_delete_credentials()`, `_exit(0)` |
| `Die` | `exit()`: the zombie, children reparented to the reaper, PR_SET_PDEATHSIG delivered if the dying parent may kill the child (`kill_ok_by_cred()`: root or the same uid), a reparented zombie announced to the reaper, `cgroup.events` when the last process leaves |
| `DispatchUserLookup` | `manager_dispatch_user_lookup_fd()` → `unit_notify_user_lookup()` |
| `DispatchPidref` | `manager_dispatch_pidref_transport_fd()` → `service_notify_pidref()` → `service_set_main_pidref()`, `unit_watch_pidref(exclusive)` |
| `DispatchHandoff` | `manager_dispatch_handoff_timestamp_fd()` → `service_handoff_timestamp()` |
| `DispatchExecFd` | `service_dispatch_exec_io()`: every queued byte sets `exec_fd_hot`, EOF drops the source and, if hot and still `Type=exec` in SERVICE_START, `service_enter_start_post()` |
| `DispatchSignals`, `DispatchSigchld` | `manager_dispatch_signal_fd()` enabling the deferred source; `manager_dispatch_sigchld()`: `waitid(P_ALL, WNOWAIT)` picks any zombie, `unit_unwatch_pidref()`, `service_sigchld_event()`, the reap |
| `DispatchCgInotify`, `DispatchCgEmpty` | `on_cgroup_inotify_event()` → `unit_check_cgroup_events()` re-reading `populated`; `on_cgroup_empty_event()` → `service_notify_cgroup_empty_event()` |
| `DispatchTimer` | `service_dispatch_timer()` in SERVICE_START, `TimeoutStartFailureMode=terminate` |
| `StopRequest`, `TimeoutFire` | `systemctl stop` (`service_stop()`), `TimeoutStartSec=` expiring |
| `EnterRunning`, `EnterStop`, `EnterSignal`, `EnterStopPost`, `EnterDead`, `SetState`, `MainExit`, `CgEmpty` | `service_enter_running()`, `service_enter_stop()`, `service_enter_signal()` with `unit_kill_context()` and the fall-through when nothing was signalled, `service_enter_stop_post()`, `service_enter_dead()`, `service_set_state()` with `SERVICE_STATE_WITH_MAIN_PROCESS()`, the main-pid branch of `service_sigchld_event()` with `is_clean_exit()`, `service_notify_cgroup_empty_event()`; the start job follows the JOB_START rule of `unit_process_job()` |

The manager dispatches the readable source with the lowest priority
number; `Prio` is the `EVENT_PRIORITY_*` table of `manager.h`
(user lookup, cgroup inotify, pidref, handoff timestamp, exec_fd, the
SIGCHLD reaper, the signalfd, the cgroup empty queue, timers).

### Switches

| Constant | Meaning |
|----------|---------|
| `Prio` | `PrioDefault` is manager.h; `PrioExecFdLate`, `PrioPidrefLate`, `PrioHandoffLate`, `PrioUserLookupLate` move one source below the SIGCHLD handling |
| `FIX_COLD_MARK` | `exec_fd_mark_hot(false)` after a failed `execve()` |
| `FIX_PAM_CLOSES_EXEC_FD` | `(sd-pam)` closes `exec_fd` (commit 5863f1da42, "execute: make sure Type=exec and PAMName= work together") |
| `FIX_PPID_CHECK` | `(sd-pam)` checks `getppid()` before `sigwait()` |
| `BARRIER` | `setup_pam()` waits for `barrier_place()` of `(sd-pam)` |
| `PAM_WAITS_FOR_PARENT` | hypothetical: `(sd-pam)` goes back to waiting when a SIGTERM finds its parent alive |
| `FIX_PIDNS_PARENT_CLOSES_EXEC_FD` | hypothetical: the `PrivatePIDs=` parent drops `exec_fd` before it lets the child go on |
| `Type`, `PAM`, `PIDNS`, `User`, `RemainAfterExit`, `KillMode` | the unit: `Type=simple\|exec\|oneshot`, `PAMName=`, `PrivatePIDs=`, `User=`, `RemainAfterExit=`, `KillMode=control-group\|mixed` |
| `StopBudget`, `TimeoutBudget`, `PayloadStatuses`, `PamDropMayFail` | the environment: stop requests, start timeouts, exit statuses of the payload, a failing `fully_set_uid_gid()` in `(sd-pam)` |

### Properties

| Property | Meaning |
|----------|---------|
| `NoLostMessage` | a datagram the executor sent, or a byte or the EOF on `exec_fd`, is never still unread when the manager reaps the process that produced it |
| `HandoffRecorded` | the handoff timestamp is attributed to the main process |
| `NoLateUserLookup` | the uid/gid resolution never reaches a unit that is already inactive |
| `ActiveImpliesExeced`, `JobDoneImpliesExeced` | `Type=exec`: the unit is active, and its start job done, only after `execve()` succeeded |
| `JobFailedImpliesNotExeced` | `Type=exec`: a payload that `execve()`d and died is "started, then failed", never "failed to start", unless a stop or a timeout intervened |
| `ExecutorSignaledOnlyOnRequest` | the manager signals a live executor or payload only on a stop request or a timeout |
| `MainPidIsTracked` | a main pid is always a watched pid |
| `StopReachesMain` | while the manager waits in a stop state for its main process, that process has been sent the stop signal |
| `InactiveImpliesNoProcess` | an inactive unit has no live process |
| `SessionNotClosedWhilePayloadAlive` | `pam_close_session()` runs only after the process that owns the session is gone |
| `JobCompletes` (liveness) | `Type=exec`: once `execve()` succeeded the start job completes |
| `SessionEventuallyClosed` (liveness) | once the process that owns the PAM session is gone, the session is closed |

Fairness is weak fairness on every step a process or the manager takes
on its own.  The environment (a payload exiting, `systemctl stop`, a
start timeout, a phase failing, the privilege drop failing) is never
forced to act, so every property also holds when it stays quiet.

### Abstractions

- One unit with one `ExecStart=`, no `ExecStartPre/Post=`, `ExecStop/Post=`,
  no notify socket, no `PIDFile=`, `ExitType=main`, `SendSIGKILL=yes`,
  `Restart=no`, no stop timeouts: a signalled process eventually dies,
  `(sd-pam)` only from SIGKILL because it blocks SIGTERM for `sigwait()`.
- `exec_invoke()` is a sequence of phases, each may fail with the EXIT_*
  code the real step uses; what the manager cannot observe between two
  phases is folded into the phase.  A pending SIGTERM or SIGKILL is
  delivered before the executor runs another phase (SIG_DFL); the payload
  may handle SIGTERM and exit on its own.
- The executor starts inside the cgroup (`CLONE_INTO_CGROUP`); every
  process of the model is in the unit's cgroup; `populated` is whether
  any of them is alive, zombies do not count (`cgroup_exit()`).
- A datagram is readable the moment it is sent, a pipe byte the moment it
  is written, EOF the moment the last write end is gone, SIGCHLD the
  moment a child of the manager exits or a zombie is reparented to it.
  The manager dispatches the highest-priority readable source, which is
  what `sd_event_wait()`/`sd_event_dispatch()` do with level-triggered
  sources and an event queue sized to the number of sources.
- The intermediary of the `FORK_DETACH` double fork is not modelled; the
  pid namespace child is a child of the manager from birth and runs as
  soon as the parent wrote the errno pipe, which is right before the
  parent's `_exit()`.
- `(sd-pam)` cannot fail on its own; `fully_set_uid_gid()` may.  The
  PR_SET_PDEATHSIG permission check is `kill_ok_by_cred()` reduced to
  "root, or the same uid".

## What the model says beyond the code

- **`systemctl stop` of a `PAMName=` service does not close the PAM
  session in either KillMode.**  With `KillMode=control-group`
  (`exec_pam_cg_stop`, `exec_pam_cg_timeout`) `unit_kill_context()`
  sends SIGTERM to the main process and to the rest of the cgroup at the
  same time; `(sd-pam)` wakes from `sigwait()`, finds `getppid() ==
  parent_pid` because the payload has not exited yet, skips
  `pam_close_session_and_delete_credentials()` and `_exit(0)`s.  When the
  payload dies there is nobody left to close the session.  With
  `KillMode=mixed` (`exec_pam_mixed`, no stop needed) the SIGTERM stage
  never touches the cgroup, so the moment the main process is gone
  `service_enter_signal()` falls through from SERVICE_STOP_SIGTERM or
  SERVICE_FINAL_SIGTERM straight into the SIGKILL of the cgroup, and
  `(sd-pam)` is killed while, or before, it runs `pam_close_session()`;
  `user@.service` is `KillMode=mixed` with `PAMName=systemd-user`.  The
  only path that closes the session reliably is `KillMode=control-group`
  with a payload that exits on its own (`exec_pam_cg`).  A `(sd-pam)`
  that keeps waiting for its parent after a SIGTERM (`PAM_WAITS_FOR_PARENT`,
  `exec_pam_cg_wait`) fixes the control-group case; nothing in `(sd-pam)`
  can fix the mixed case.
- **The barrier in `setup_pam()` is what makes `Type=exec` and `PAMName=`
  work together, not a privilege ordering.**  `(sd-pam)` closes `exec_fd`
  before `barrier_place()`, and the executor waits for that before it
  goes on.  Without the barrier (`exec_pam_nobarrier`) a payload that
  `execve()`s and dies while `(sd-pam)` has not run yet keeps the EOF
  from the manager until `(sd-pam)` gets around to closing the fd, the
  SIGCHLD comes first, and the unit fails to start instead of starting
  and failing.  For `Type=simple` nothing depends on the barrier
  (`simple_pam_nobarrier`), and the `getppid()` check it is documented
  to complement is not needed in any configuration of the current kill
  logic (`exec_pam_noppid`, `simple_pam_nobarrier_noppid`): a
  `(sd-pam)` whose parent died before PR_SET_PDEATHSIG was armed is
  woken by the cgroup SIGTERM of `KillMode=control-group`, and under
  `KillMode=mixed` it is killed anyway.
- **`PrivatePIDs=` holds `exec_fd` in the parent for a moment too
  long.**  `setup_private_pids()` writes the errno pipe that lets the
  child continue and only then `_exit()`s; between the two the parent
  still holds the write end of `exec_fd`.  A payload that `execve()`s
  and dies before the parent got scheduled again is reaped with the EOF
  still pending, and a `Type=exec` unit fails to start instead of
  starting and failing (`exec_pidns`).  A parent that closes `exec_fd`
  before the errno write passes every property (`exec_pidns_fix`).
- **A stop that lands in that same window is lost for
  `KillMode=mixed`.**  The SIGTERM goes to the parent, which is the main
  pid at that time; the pidref handoff then makes the child the main
  pid, the parent's SIGCHLD is ignored, and the manager waits in
  SERVICE_STOP_SIGTERM for a child nobody signalled, until
  `TimeoutStopSec=` sends SIGKILL (`exec_pidns_stop`).
  `KillMode=control-group` is unaffected: the cgroup kill reaches the
  child (`exec_pidns_stop_cg`).
- **`PAMName=` with `PrivatePIDs=`, which `unit_verify_contexts()`
  refuses, would close the session at the start of the service**: the
  parent's `_exit()` after the pidref handoff fires PR_SET_PDEATHSIG in
  `(sd-pam)`, whose parent it is, while the child is still setting up
  (`exec_pam_pidns`).
- **Each priority in `manager.h` has a trace.**  `exec_fd` below the
  SIGCHLD handling turns "started, then died with status 1" into a failed
  start job (`exec_execfd_late`) and drops the readable EOF on the floor
  (`exec_execfd_late_lost`); the pidref below it makes the parent's
  exit stop the service and kill the child (`simple_pidns_late`); the
  handoff timestamp below it is attributed to nobody
  (`exec_handoff_late`); the user lookup below it references a uid/gid
  on a unit that already failed (`exec_ul_late`).  All of them are
  instances of `NoLostMessage`: every source the executor writes to sits
  above SIGCHLD, and the kernel makes each of them readable before the
  process can exit.
- Patches for the first four items are on the systemd branch
  `work.systemd.executor.races`: `(sd-pam)` polls a pidfd of its parent
  and keeps SIGTERM blocked, the `PrivatePIDs=` parent closes `exec_fd`
  before the errno write, `service_notify_pidref()` repeats the stop
  signal for the child, and `KillMode=mixed` sends the cgroup the
  terminate signal first once the main process is gone.  Their tests:
  `src/test/test-service.c` (the stop signal repeated on the handoff),
  `test/units/TEST-07-PID1.kill-mode-mixed.sh`,
  `test/units/TEST-07-PID1.pam-session.sh`, and the
  `type_exec_quick_exit` case of `TEST-07-PID1.private-pids.sh`;
  `vm-run-tests.py` here runs the shell ones in a VM of any tree.
- **`Type=simple` is started at spawn**, so `ActiveImpliesExeced` cannot
  be asked of it: an executor that fails in `exec_invoke()` fails a unit
  that was already active.  The model only asks it of `Type=exec`.
