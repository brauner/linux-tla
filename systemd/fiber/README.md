# TLA+ model of systemd's fiber runtime (sd-future)

Tree: systemd v262-rc3 (e96ff3b5b9).

`src/libsystemd/sd-future/fiber.c` runs code on separately mmap'd stacks and
switches between them with sigsetjmp()/siglongjmp(); `sd-future.c` wraps
every long-running operation in an `sd_future` that resolves exactly once;
`sd-event/event-future.c` turns io and timer event sources into such
futures.  A fiber is driven by two sd-event sources, a defer source while the
loop runs normally and an exit source once `sd_event_exit()` has been called,
and it suspends by switching back to whichever `fiber_run()` entered it.  A
future created on a fiber resumes that fiber when it resolves; `sd_fiber_*`
wrappers (sleep, read/write, bus calls, `sd_event_run()` on an inner loop)
are "create the future, suspend, clean the future up".  Cancellation is
cooperative: `sd_future_cancel()` on a fiber future makes its next
`sd_fiber_yield()`/`sd_fiber_suspend()` return -ECANCELED and the fiber
unwinds through its `_cleanup_` attributes, every owned future released with
`sd_future_cancel_wait_unref()`.

The model is one event loop, up to four fibers and the futures they create.
Fibers run any program of a few operations each (yield, wait for an
io/timer/bus future, spawn an owned or floating child, await a fiber, cancel
one, request exit, timeout scopes, a bare suspend), errors unwind the stack
with the cleanups, main may request exit or cancel a fiber between iterations,
the kernel fires events whenever it likes.  The loop dispatches one source per
iteration in sd-event's order (priority, then the iteration a source became
pending in, ties arbitrary).  Each candidate fix is a switch.

## Design assessment

The question behind the model was whether the fiber runtime, as merged, is
safe to build on. As of e96ff3b5b9 it is not, for three structural reasons
and one refcounting bug; each is proven twice, by a TLC counterexample and by
a C test that fails on a pristine build of that commit (the tests are the
ones on `work.systemd.fiber`, run with `TESTFUNCS=<name> build/test-fiber`
against `jens:src/git/systemd-fiber-orig`). What the failures mean depends on
the build: developer builds abort on an assertion; release builds
(`-Db_ndebug=true`, as `.github/workflows/build-test.sh` uses, where
systemd's `assert()` becomes `__builtin_unreachable()`) corrupt memory. A
release-mode build of the pristine tree with the sanitizers on
(`-Dmode=release -Db_ndebug=true -Db_sanitize=address,undefined`, and once
more with `address` alone so that ASan gets to see what follows the
unreachable point) reports:

| Test on the pristine tree | Developer build | Release build with sanitizers |
|---|---|---|
| `future_unref_pending` | abort, `sd_future_ref()` asserts `n_ref > 0` | UBSan: unreachable program point in `sd_future_ref()`; with ASan alone: heap-use-after-free in `sd_future_free()` on the object the recursive free inside `sd_future_resolve()` released |
| `fiber_cancel_wait_unref_survives_cancel` | abort, same assertion (the child is freed while pending) | same, reached from `sd_future_cancel_wait_unref()` |
| `fiber_cancel_during_cleanup_not_lost` | abort, same | same |
| `fiber_floating_child_outlives_floating_parent` | `assert_return()` in `sd_fiber_resume()` reads the freed future | ASan: heap-use-after-free in `sd_future_get_ops()` from `sd_fiber_resume()` from `fiber_resume_trampoline()` |
| `fiber_sleep_survives_child_completion` | the parent's 30 ms sleep returns the child's -EIO | same |
| `fiber_deadline_while_queued` | the deadline is dropped, the yield returns 0 | same |
| `fiber_exit_unwinds_child` | the child is never run again after the exit | same |
| `fiber_cancel_running` | abort, `fiber_cancel()` asserts | unreachable program point |
| `fiber_handle_dropped_while_running` | abort, `sd_future_ref()` asserts (the live child is freed) | heap-use-after-free in `sd_future_free()` |
| `fiber_wait_refused_while_exiting` | the loop finishes with the fiber suspended; `sd_future_result()` asserts | same, unreachable program point |

The three structural problems, and what the fixes change about the design:

1. **Waits have no provenance.** A fiber has a single wakeup channel (the
   `result` stashed by `sd_fiber_resume()` and the SUSPENDED → READY
   transition) and every future created on the fiber uses it, including the
   fiber's own children. Every wait primitive (`sd_fiber_sleep()`,
   `sd_fiber_await()`, the I/O wrappers, `event_run_suspend()`,
   `bus_call_suspend()`) returned on the first resumption and took its value as
   its own outcome. The consequence is that no two pending futures on one
   fiber compose: a parent that has spawned a child cannot sleep, read or
   await anything reliably, and a fiber that started a bus or QMP call it has
   not awaited yet cannot either. `asis_spurious_child*`; finding 4. The fix
   records what resumed the fiber and makes each wait loop until its own
   future has resolved, with only a cancellation, an `SD_FIBER_TIMEOUT()`
   deadline or an explicit `sd_fiber_resume()` allowed to cut in; a fiber's
   own future no longer resumes its creator at all. `sd_fiber_suspend()` keeps
   the old "any resumption" semantics as the low-level primitive.

2. **Cancellation is a flag that one wait consumes.** `fiber_cancel()` sets
   the CANCELLED state, the next `fiber_swap()` returns -ECANCELED and the
   state is gone. A wait that has to complete regardless, namely the wait for
   a cancelled child in `sd_future_cancel_wait_unref()`, either returned
   early (and freed a live fiber) or, once fixed to wait on, would swallow the
   cancellation. Deadlines have the same problem: the -ETIME of an
   `SD_FIBER_TIMEOUT()` scope is a value delivered once, and a fiber that is
   not suspended at that moment loses it for good. `asis_cwu_*`,
   `asis_lost_cancel*`, `asis_void_deadline*`, `asis_stale_yield`; findings
   2, 5, 6. The fix adds a per-fiber `pending_result`: a cancellation, a
   deadline or an explicit resume that a cleanup wait consumed, or that a
   cancellation superseded, is returned by the fiber's next wait; and a
   deadline or explicit resume aimed at a fiber that is queued to run
   replaces a success it has not seen yet.

3. **Unwinding at exit depends on user discipline.** The guarantee that every
   fiber's stack is unwound before the loop finishes rested on the exit event
   source, which only fibers created outside a fiber got; children were the
   parent's job, through `sd_future_cancel_wait_unref()`. A floating child, a
   child cancelled before the exit, or a child cancelled from outside a
   dispatch after its exit source had fired once, was left with a live stack
   when `sd_event_loop()` returned. `asis_stranded_floating_child`,
   `abl_no_exitarmed*`; finding 3. The fix keeps every fiber's exit source
   armed for as long as it lives; combined with 2. the exit path is then
   proven to unwind every fiber whatever the nesting (`fixed_*`,
   `FinishedImpliesUnwound`).

And the refcounting bug (finding 1): freeing a pending future takes a
reference on an object whose count is already zero. Every error path that
drops a future it just created runs into it.

Two more holes in the contract were closed after the first round, both
found by asking what the fixes still leave undefined rather than by the
model (the tests fail on the pristine tree; `fiber_handle_dropped_while_running`
with the `n_ref > 0` assertion, `fiber_wait_refused_while_exiting` with the
loop finishing around a suspended fiber):

- Dropping the last reference to a fiber's future while its stack is live
  was undefined: developer builds assert in `fiber_free()`, release builds
  unmap a stack with live frames on it, from something as ordinary as a
  `_cleanup_(sd_future_unrefp)` on a child in an error path. 2a4d49719e: a
  fiber holds a reference on its own future from its first run until it
  resolves, so a dropped handle lets it run to completion and free itself.
- A wait entered after `sd_event_exit()` on anything but a fiber (an io,
  timer or bus future) can never complete, since the loop dispatches nothing
  but exit sources from then on; the fiber stayed suspended when the loop
  finished. e00a9ff1ab: such a wait returns -ECANCELED right away.

What remains by design: unwinding is cooperative. A fiber's stack can only
be reclaimed by the fiber returning through its frames, so a fiber that
ignores -ECANCELED and never completes keeps its stack and everything it
owns for the life of the process; the runtime delivers the cancellation
(once per `sd_future_cancel()`, and once more per exit dispatch while the
exit source stays armed) but cannot force the unwind, which is inherent to C
with `_cleanup_` attributes. The raw `sd_fiber_suspend()`/`sd_fiber_resume()`
pair still returns on any resumption; it is the primitive for protocols
that resume explicitly, and every wait for a particular future has to go
through `fiber_await()`, which would need to be part of the API if sd-future
is ever exported. The `userdata` a fiber runs with is the caller's to keep
alive, as for any callback.

## Findings

Every finding below reproduces against the code as it is (the `asis_*`
configurations), and every fix is a switch in the model; the `abl_*`
configurations show which fix each property needs. The C fixes are on branch
`work.systemd.fiber` (worktree `~/src/git/systemd-worktrees/work.systemd.fiber`),
one commit per fix followed by its tests; every new test was also run against
a pristine build of e96ff3b5b9 and fails there the way the finding says.

1. **Dropping the last reference to a pending future aborts.**
   `sd_future_free()` runs with `n_ref == 0` and resolves a pending future
   with -ECANCELED first, but `sd_future_resolve()` takes a temporary reference
   and `sd_future_ref()` asserts `n_ref > 0`. Every error path after a future
   was created ends there: `sd_fiber_new()` failing after `sd_future_new()`,
   `future_new_io()` when the fd cannot be duplicated, `bus_call_future()` when
   `sd_bus_call_async()` fails, `sd_future_cancel_wait_unref()` outside a
   fiber. Found by reading (the model has no operation for those paths; its
   `FixFreePending` switch only changes what crashes in finding 2). Fix:
   89adec160d, test `future_unref_pending`.

2. **`sd_future_cancel_wait_unref()` frees a fiber that is still running.**
   (`asis_cwu_exit_race`, `asis_cwu_cancel_race`, `asis_cwu_sibling_race`,
   `abl_no_cwuloop`.) It cancels the child and waits for *one* resumption,
   whatever caused it. When the waiting parent is itself cancelled meanwhile
   (the loop exiting, a sibling, the main program) the wait returns -ECANCELED,
   the parent drops its reference while the child is still pending, and
   `fiber_free()` asserts on the live stack (or finding 1 fires first). The
   cancellation is also swallowed: `asis_lost_cancel`, `asis_lost_cancel_exit`,
   `abl_no_recancel*`: after the wait at the end of an
   `SD_FIBER_WITH_TIMEOUT()` block the fiber carries on as if it had not been
   cancelled, and if that was the loop exiting it suspends again and is never
   unwound. Fix: 5f8bd50488 (`FixCwuLoop` + `FixRecancel`), tests
   `fiber_cancel_wait_unref_survives_cancel`,
   `fiber_cancel_during_cleanup_not_lost`.

3. **Fibers created on a fiber are stranded when the loop exits.**
   (`asis_stranded_floating_child`, `abl_no_exitarmed*`.) Their exit source
   was disabled on the theory that the parent cancels them. A floating child
   (`sd_fiber_new()` with a NULL `ret` from inside a fiber) has no such parent;
   a child cancelled before `sd_event_exit()` sits on its defer source, which
   is never dispatched again. Either way the loop finishes with the fiber's
   stack never unwound: cleanups don't run, the future and the stack leak, an
   owner's final unref asserts. `abl_no_exitarmed_cancel` adds the case of a
   cancel from the main program after the fiber's exit source fired once,
   which with the original "exit source only while exiting" rule armed the
   defer source and stranded the fiber too. Fix: 38e2c9c03f (`FixExitArmed`):
   every fiber's exit source is armed at creation and re-armed whenever the
   defer source is. Test `fiber_exit_unwinds_child`.

4. **Every future created on a fiber resumes it, and every wait takes any
   resumption as its own.** (`asis_spurious_child`,
   `asis_spurious_child_fails`, `asis_uaf_floating_child`,
   `abl_no_childtramp_floating`.) A child completing ends its parent's
   `sd_fiber_sleep()` early with the child's result (a failing child turns
   into the parent's sleep error), `sd_fiber_read()` returns -EAGAIN,
   `sd_fiber_await()` returns before its target resolved (and
   `sd_future_result()` on the target then fails with -EBUSY), a bus call
   returns without a reply. A floating child outliving a floating parent
   resumes the parent's freed future. Fixes: 7f786c1199 (`FixAwaitLoop`:
   `fiber_await()` records what resumed the fiber and only a cancellation, an
   `SD_FIBER_TIMEOUT()` deadline or an explicit `sd_fiber_resume()` end a wait
   for something else) and 2b3246ed31 (`FixNoChildTrampoline`: a fiber's own
   future has no completion callback). Tests
   `fiber_sleep_survives_child_completion`,
   `fiber_await_survives_other_completion`,
   `fiber_floating_child_outlives_floating_parent`.

5. **A deadline that fires while the fiber is queued is lost.**
   (`asis_void_deadline`, `asis_void_deadline_io`, `asis_void_deadline_live`,
   `abl_no_sticky`.) `sd_fiber_resume()` acts only on a suspended fiber. A
   fiber that yielded, or that another future resumed, and that is waiting to
   run again drops the deadline's -ETIME; the timer has resolved, and every
   later wait inside the scope is unbounded (`asis_void_deadline_live` is a
   deadlock for TLC). It takes a yield after the deadline expired but before
   its timer was dispatched: sd-event dispatches sources of equal priority in
   the order they became pending, so the trace is `SD_FIBER_TIMEOUT()`, two
   yields, a wait. Fix: d49958e76a (`FixStickyError`): an error from a
   deadline or an explicit resume replaces a success the queued fiber has not
   seen yet. Test `fiber_deadline_while_queued`.

6. **A resume value superseded by a cancellation surfaces from a later
   yield.** (`asis_stale_yield`.) The -ECANCELED return of `fiber_swap()` left
   the stashed value in place. Fix: part of 5f8bd50488, test
   `fiber_stale_resume_value_dropped`.

7. **Cancelling a running fiber.** Not modelled (no inner event loops in the
   model), found by reading: `fiber_cancel()` asserted that its target is not
   the current fiber and mishandled a running fiber that is not the current
   one (an outer fiber dispatching an inner loop): an INITIAL fiber was
   resolved while running, a READY one was marked cancelled with its defer
   source armed, which trips `fiber_run()`'s state assertion once it
   suspends. The assertion also made a fiber-dispatched bus method handler
   that closes its bus (`bus_enter_closing()` cancels every handler,
   including the caller) abort. Fix: part of d49958e76a: a running fiber
   sees the cancellation at its next wait. Test `fiber_cancel_running`.

## Beyond the code

- **Inner event loops.** `event_run_suspend()` (an `sd_event_run()` on a
  fiber) is not in the model: it lets an outer fiber run while it is not the
  current one, which is what finding 7 is about. The `running` flag covers
  the cancel; a deadline of the outer fiber cannot fire while it runs (its
  timer lives on the outer loop, which is blocked in the fiber's dispatch).
- **Fibers that ignore their cancellation.** `fixed_ignore_errors` lets fibers
  carry on after -ECANCELED. Two such fibers awaiting each other while the
  loop exits deadlock, and one suspending on something nothing will resolve
  during the exit is stranded; that is the program's doing, the runtime
  delivers the cancellation once per `sd_future_cancel()` (and once more per
  exit dispatch while the exit source stays armed). The configuration
  therefore has no bare suspends and no awaits.
- **`sd_event_set_exit_on_idle()` hides a lost deadline**: a fiber suspended
  forever with its deadline gone leaves the loop idle, the loop exits and
  cancels it. `fixed_idle` passes for that reason as much as for the fix; the
  safety property `NoVoidDeadline` does not depend on it.
- **`sd_fiber_ppoll()`** returns 0 ("timed out") when an explicit
  `sd_fiber_resume()` with a non-negative value or a stale readiness ends its
  wait with no fd ready and no timer expired; pre-existing, not modelled.
- **Out of memory in a cleanup.** `sd_future_cancel_wait_unref()` needs a wait
  future to wait for the child; if that allocation fails it logs and drops its
  reference anyway, which is finding 2 all over again. The alternative would
  be to leak the child on purpose.
- **Liveness needs a bounded adversary.** An environment that cancels a fiber
  again every time it suspends, while TLC keeps picking that fiber's exit
  source over its child's (equal priorities are dispatched in heap order,
  which the model leaves arbitrary), starves the child forever: the parent
  never completes. No real caller cancels the same fiber unboundedly often,
  so the liveness configurations bound main's cancels (`MainCancelMax`);
  safety configurations leave them unbounded.
- **What the model takes as given about sd-event**: one source dispatched per
  iteration, pending sources ordered by (priority, iteration they became
  pending in) with arbitrary ties, exit sources ordered by priority only,
  `exit_on_idle` evaluated in `sd_event_prepare()`, and a source disabled
  from its own callback freed after the callback returns. Kernel events
  (timers, io, bus replies) are one nondeterministic action each, with weak
  fairness where liveness is checked.
- **Not modelled**: the bus's `fiber_futures` set and `process_closing()`
  drain, varlink's fiber methods and their priority trick, `run_main_fiber()`
  (a floating top-level fiber, `fixed_floating`), the atfork handler, the
  fiber-aware `loop_read()`/`loop_write_full()`/`pidref_wait_for_terminate()`
  in src/basic (they are `ext` waits inside a deadline scope), stacks,
  signals and log context.
